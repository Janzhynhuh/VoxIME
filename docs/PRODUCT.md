# VoxIME 产品说明书（PRD）

> 版本：v0.1 规划稿 · 定位：Windows 桌面端「语音输入 + 桌宠」工具

## 1. 背景与问题

- 键盘输入中文仍有速度瓶颈，尤其长句、口语化表达、双手被占用（编程、设计、会议记录）时效率低。
- 系统自带语音输入（Win+H）识别由微软垄断、不支持自定义厂商，也不支持本地离线模型；商业输入法的语音功能绑定自家云服务，无法接入企业私有 ASR / 自建大模型。
- 中文互联网用户（二次元、VTuber、桌宠爱好者）希望桌面有一个"活"的虚拟形象，但目前语音输入与 Live2D 桌宠是两个割裂的工具。

**机会**：做一个"语音输入 + 可插拔 ASR + Live2D 桌宠"的桌面小工具，把识别能力选择权交给用户，同时提供情绪价值。

## 2. 目标用户

| 画像 | 场景 | 关键诉求 |
|---|---|---|
| 效率型用户（程序员/产品/运营） | 长文档、聊天、代码注释口述 | 快、准、任何输入框可用、少打断 |
| 隐私敏感用户（法务/医疗/政企） | 内部资料口述 | 本地离线、数据不出本机 |
| 多模型玩家（AI 爱好者） | 折腾各家 ASR/大模型 | 自定义 BaseUrl/模型、多配置快速切换 |
| 二次元/桌宠用户 | 桌面陪伴 + 语音互动 | Live2D 形象、口型同步、状态联动 |
| 内容创作者 | 口播转文字、直播字幕辅助 | 低延迟、可编辑、历史可回溯 |

## 3. 产品定位与差异化

一句话：**「一个能换语音模型、能养 Live2D 老婆的 Windows 语音输入法」**。

| 维度 | 系统语音输入 | 商业输入法语音 | VoxIME |
|---|---|---|---|
| 厂商可换 | ❌ | ❌ | ✅ OpenAI 兼容/小米 MiMo/DashScope/腾讯/讯飞/本地 CLI |
| 本地离线 | 部分 | 部分 | ✅ whisper.cpp/FunASR/sherpa-onnx |
| 任意输入框 | ✅ | ✅ | ✅（管理员窗口例外） |
| Live2D 桌宠 | ❌ | ❌ | ✅ 模型自备、状态/口型/眼动联动 |
| 可定制/可扩展 | ❌ | ❌ | ✅ 开源、适配器即插即用 |
| 隐私 | 系统云 | 厂商云 | 本机保存 + 本地模式 |

## 4. 功能需求

### P0（v0.1 必须）
1. 全局热键：按住说话、按下切换两种模式，每个功能可配置多个热键（键盘组合、F1-F24、鼠标侧键/中键，任意一个触发）；录音中可取消。
2. 录音：麦克风设备选择、16kHz 单声道、能量 VAD、静音自动结束、最长时长限制、提示音。
3. 多厂商 ASR：OpenAI 兼容接口（文件）、OpenAI Chat Audio（MiMo/DashScope）、腾讯云、讯飞、本地 CLI、Mock；可配置多套服务并切换默认。
4. 上屏：剪贴板粘贴优先、模拟输入兜底、可配置预览确认、自动追加空格/回车、术语替换、剪贴板还原。
5. 结果展示：HUD 状态条（聆听/识别/错误）、实时麦克风电平、预览编辑、插入/复制/取消。
6. 历史：本地记录（时间/文本/服务/时长/延迟），可复制、清空。
7. Live2D：透明置顶窗口、加载 Cubism 3/4/5 模型、待机动画、状态联动、口型（麦克风）、眼动跟随、气泡字幕、点击穿透、位置/大小/透明度/缩放；无模型时兜底形象。
8. 设置中心：服务/录音/上屏/桌宠/朗读/通用/外观七个页签，保存即生效；首次启动引导。
9. 托盘：显示/隐藏桌宠、开启/关闭桌宠点击穿透（免进设置）、暂停热键、设置、历史、日志目录、退出；开机自启。
10. 安全：API Key 明文保存在本地配置；配置/历史/日志本地方案；日志脱敏；配置可导入导出。
11. 外观：明暗主题（跟随系统 / 浅色 / 深色）与 7 套配色（VoxIME 石墨、Nord、Rosé Pine、Catppuccin Latte / Frappé / Macchiato / Mocha），切换即时生效，跟随系统时随 Windows 应用模式自动切换。
12. 背景与动效：设置/历史/关于/欢迎窗口支持自定义背景（本地图片/纯色/渐变 + 透明度/模糊/暗化/填充/玻璃强度），可按背景亮度一键匹配浅色/深色主题（文字颜色随主题自动适配）；录音悬浮窗（HUD）在外观页可单独设置自定义背景（同样支持纯色/渐变/图片 + 透明度/模糊/暗化/填充）、窗口缩放（70%–150%）、圆角、整体不透明度与默认位置，并提供实时预览面板，与其它窗口互不影响；界面动效三档（明显/克制/关闭），设置页滚轮平滑惯性；Live2D 桌宠保持原样。

## 5. 核心交互流程

```
[任意应用输入框] 按住 Ctrl+Alt
      ↓
HUD 出现：🎙 聆听中（电平环呼吸）   桌宠：聆听动作 + 口型
      ↓ 松开
HUD：识别中（转圈）                 桌宠：思考动作
      ↓
文字粘贴到光标处 + HUD 显示结果      桌宠：气泡显示 + 朗读/口型（可选）
      ↓ 自动消失
```

异常路径：
- 没有检测到语音 → HUD 提示"没有检测到语音（输入峰值 X% / 检测阈值 Y%）"，提示检查设备或调低「语音检测阈值」。
- 识别失败 → HUD 红色提示 + 托盘气泡，桌宠 Error 动画，3.5s 恢复。
- 上屏失败 → 文本自动复制到剪贴板，HUD 提示"已复制，请手动粘贴"。
- 用户取消（Esc/再次按切换键）→ 立即停止、丢弃本轮。

## 11. 待实现需求：Live2D 按显示配置记忆窗口几何

> 状态：**待实现**（2026-11-03 记录，等当前远程桌面物理吸附验证稳定后再做）。
> 不要在未验证当前物理吸附/DPI 校准前与临时诊断一起实现。
> 2026-11-04：UU远程（GameViewer）默认镜像主屏，按显示器 key 的实现尝试无效，已回退
> （`60d7715`、`8b78f0e` → `76971ca`）；需先解决"远程镜像会话识别"，再重新实现。

### 11.1 背景

远程控制软件（RDP / UU远程 / ToDesk / 向日葵等）切换屏幕时，Windows 不一定“新增一块屏”：

- 可能替换本地多屏布局为远程单屏/多屏；
- 可能只改现有显示器分辨率、工作区或 DPI；
- 虚拟显示器可能被创建/销毁；
- `WM_DISPLAYCHANGE`、WPF `SystemParameters`、`GetMonitorInfo`、窗口 DPI/物理尺寸不是同时更新。

因此绝对坐标（`Left/Top`）在切换后会失效，表现为桌宠消失、落在错误屏幕、任务栏吸附失效或大小跳变。现有修复先用物理像素兜底，但长期需要“每套显示配置记住自己的位置和大小”。

**UU远程（GameViewer）默认镜像主屏**：系统不会新增/替换显示器，也不会置位 `SM_REMOTESESSION(0x1000)`；本地与远控看到的是同一块显示器，显示器 key/分辨率/适配器名完全一致，按显示器区分位置在本场景不成立。另外，仅有 `GameViewer.exe` 进程或虚拟显示适配器存在 ≠ 当前正在被远控，不能作为可靠的“远控中”判据。

### 11.2 目标

同一个桌宠窗口在不同显示配置间切换时，各自恢复自己的位置、尺寸和吸附状态：

- 本地双屏 ↔ 远控单屏；
- 分辨率/DPI 变化；
- 显示器插拔、主屏切换；
- 切换到未知新显示配置时有安全默认值。

### 11.3 需求

1. **显示配置 key 必须稳定**
   - 使用显示器设备标识 + 物理 bounds + 工作区 + DPI 组合；
   - 不使用屏幕序号/枚举顺序作为主键；
   - 拿不到设备标识时退回 bounds+workArea+DPI 签名。

2. **保存相对几何，不保存绝对像素**
   - `xRatio = (left - work.left) / work.width`
   - `yRatio = (top - work.top) / work.height`
   - `widthRatio = width / work.width`，`heightRatio = height / work.height`
   - 同时保存 `snapToEdge`、`keepAboveTaskbar`；
   - 恢复时按目标工作区换算并 clamp 到可见范围；显示器更小时允许收缩。
   - 尺寸策略需固定：按工作区比例恢复，或按当前 DPI 的 DIP 尺寸恢复；二者选一并写入文档/测试。

3. **显示切换流程**
   - 显示事件后 debounce 300~500ms，等 WPF/Win32 参数稳定；
   - 只有用户拖过窗口才更新旧显示配置，避免启动/自动吸附覆盖；
   - 恢复目标显示配置；没有记录则使用当前屏右下角默认位置；
   - 恢复后做一次物理吸附/DPI 校准，处理 WPF 逻辑尺寸与物理尺寸不一致；
   - 事件风暴要合并，不能反复弹跳。

4. **配置模型**
   - `Live2DConfig` 增加按显示配置的 placement 集合；
   - 保留现有 `Left/Top/Width/Height/SnapToEdge` 作为兼容回退；
   - 旧配置首次启动时迁移为“当前显示配置”的一条记录；
   - 未知显示配置不报错，使用默认值并允许后续记住。

5. **范围**
   - 只记忆窗口几何，不按屏幕切换模型/表情/动作；
   - 仍只有一个桌宠窗口；
   - 不改变现有模型资源/动作/表情逻辑。

6. **远程镜像模式识别（UU远程镜像主屏场景）**
   - 优先做只读调研：UU远程被控时是否有可稳定检测的信号（进程/窗口/服务/命名管道/网络连接/注册表）；
   - 若能可靠检测 → 维护「本地位置 / 远程位置」两套记录，按会话状态切换；
   - 若不能可靠检测 → 提供**手动切换**（托盘/设置中“记住当前位置为远程位置 / 切回本地位置”），不做猜测性自动判断；
   - 明确禁止把“进程存在”当成“正在远控”的启发式写进核心逻辑。

### 11.4 验收标准

- [ ] 本地双屏 ↔ 远控单屏切换后，两边各自恢复之前的位置/大小/吸附状态。
- [ ] 远控切换后桌宠不消失、不缩到屏幕外、不突然变大。
- [ ] 远控屏和本地屏拖到任务栏都能正常吸附。
- [ ] 分辨率/DPI 变化后窗口尺寸合理，不依赖 WPF `ActualWidth` 与 `Width` 恰好一致。
- [ ] 显示器插拔、主屏切换、未知虚拟屏都有安全默认位置。
- [ ] 旧配置可直接升级，不丢失当前桌宠位置。
- [ ] 新增单测覆盖：配置 key 生成、相对坐标换算/clamp、旧配置迁移、未知配置回退。
- [ ] UU远程镜像主屏模式下：本地与远程各记住一个位置，切换后可恢复（自动检测或手动切换二选一，按 11.3 结论）。
- [ ] 文档同步 `docs/live2d.md` 与 `docs/CONTRACTS.md`。

### 11.5 明确不做

- 不按显示器记忆不同的 Live2D 模型；
- 不做多桌宠实例；
- 不把远程桌面软件特有的坐标/会话 API 写进核心逻辑；核心只依赖 Win32 显示器与窗口几何。

## 12. 待实现需求：代码签名与 SmartScreen 信誉

> 状态：**暂不实施**（2026-11-03 记录，等确定证书/签名路线后再做）。
> 当前 v0.4.2 的安装版和免安装版均未签名。

### 12.1 背景

- 安装版 `VoxIME-Setup-*.exe` 和免安装版 `VoxIME.exe` 未签名，首次运行会触发 SmartScreen「无法识别的应用」。
- 每次重新构建都会改变文件哈希，SmartScreen 信誉从零开始，不能靠旧版本“仍要运行”的记录继承。
- 安装器会写文件、创建快捷方式、写卸载信息，启发式上比普通 exe 更敏感，但没有代码签名时更容易被标成未知发布者。
- 已确认是 SmartScreen 信誉问题，Defender 保护历史中没有 VoxIME 相关威胁记录；这不是病毒误报。

### 12.2 目标

- 发布的 `VoxIME.exe` 和 `VoxIME-Setup-*.exe` 显示可信发行者。
- EV 证书优先做到 SmartScreen 直接信任；OV/开源证书至少显示发行者并逐步积累信誉。
- 证书私钥不进入仓库、构件或 CI 日志。

### 12.3 候选路线

1. **EV 代码签名证书**：正式商业分发首选，SmartScreen 体验最好，成本/审核最高。
2. **OV 代码签名证书**：成本较低，但可能仍需信誉积累。
3. **开源项目签名**：项目代码为 MIT、仓库公开，可评估 SignPath Foundation / Certum OSS 等；需人工审核，且要如实披露 Live2D 等第三方许可。
4. **自签名证书**：仅本地测试；其他电脑不信任，不作为发布方案。

### 12.4 需求

1. 签名范围：
   - 先签 `VoxIME.exe`（安装包/免安装版共用同一二进制）
   - 再签 `VoxIME-Setup-*.exe`
   - Inno Setup 卸载器 `unins*.exe` 尽量也签（`SignTool` + `SignedUninstaller=yes`）
2. 签名参数：
   - SHA-256 摘要
   - RFC3161 时间戳（如 DigiCert/Sectigo）
   - 签名后用 `signtool verify /pa /v` 验证
3. 自动化：
   - 新增可选 `scripts/sign.ps1`；证书指纹/云签名配置走环境变量
   - CI 使用 GitHub Secrets 或云签名服务；禁止把 PFX/密码写进仓库
   - 没有证书时构建流程保持可用，只跳过签名
4. 发布一致性：
   - 一个版本只发布一个签名后的哈希；签名会改变文件哈希
   - 签名后重新生成/上传 Release 资产，并更新 README/Release 备注中的 SHA256
5. 用户侧：
   - 未签名期间 README/FAQ 明确写「更多信息 → 仍要运行」
   - 不推荐关闭 SmartScreen/Defender
   - 只有 Defender 真正报出威胁名时才走误报提交；SmartScreen 未知发布者不等于病毒误报

### 12.5 验收标准

- [ ] `Get-AuthenticodeSignature` 显示 `Valid`，发行者不再是未知。
- [ ] `signtool verify /pa /v` 对 `VoxIME.exe`、Setup、卸载器均通过。
- [ ] 签名带有效时间戳，证书到期后旧签名仍可验证。
- [ ] 新版本首次下载运行时 SmartScreen 不再提示，或至少显示可信发行者。
- [ ] 私钥/密码未出现在 git、构建产物、日志或 GitHub Actions 输出中。
- [ ] 签名后的 Release 资产哈希已更新并验证。
- [ ] 文档同步 `README.md`、`AGENTS.md` 和发布说明。

### 12.6 明确不做

- 不做自签名证书的正式分发；
- 不通过修改系统 SmartScreen 设置来掩盖问题；
- 不把证书、Token、密码提交到仓库或上传到 Release。
